# Migration Plan

This page defines the spec-driven migration of Registry: a ground-up **Vue 3 + Nuxt (SSR)** frontend rewrite with **Ant Design Vue**, alongside independent backend tracks for **API v2**, performance, and security hardening. It is a planning artifact — the source of truth for *what specs to write, in what order, and behind which gates*. Each change below is realized as a spec (functional where behaviour changes, then an ADR) **before** any implementation, per the repository's functional-first-then-technical workflow.

> **Working agreement — validate each pattern before propagating.** During implementation, every distinct pattern (a component built on Ant Design Vue, a Pinia store/facade, a cached query, an SSR-auth route, a v2 endpoint, a test shape) is implemented **once** as a reference instance, presented for validation, and only **then** replicated across the codebase. The first vertical slice of each ADR is that checkpoint.

## Guiding principles

1. **The REST contract is the seam.** Backend and frontend are independently deployable, so the backend tracks run **in parallel** with the frontend rewrite, and the new frontend is born consuming **API v2**.
2. **Spec-first gating.** Functional / security baseline first, then technical ADRs, then code. Nothing in `technical/` is drafted before its functional and roles baseline is settled.
3. **The rewrite window is used once.** Accessibility, the design system, SSR, and data-caching are **baked into the rewrite specs**, never retrofitted onto the Angular app.
4. **De-risk early.** The rewrite is committed (ADRs 011/012/013/014/022/023 Accepted); a Phase-0 spike still runs first to de-risk the hard mechanics (SSR + OIDC auth, Ant Design Vue under SSR, Nuxt runtime config) before broad implementation.

## Settled decisions

| Decision | Choice |
| -------- | ------ |
| Frontend framework | **Vue 3 + Nuxt** — full rewrite (committed); Phase-0 spike de-risks early |
| Rendering | **Full SSR** — reworks the auth model ([ADR 004](/registry/technical/adr/004-oidc-resource-server-auth)); de-risked in the spike |
| Design system | **Ant Design Vue** (replaces PrimeNG; PrimeVue excluded — same licensing) |
| State management | **Pinia** — supersedes [ADR 009](/registry/technical/adr/009-ngxs-state-management) (NGXS) |
| Accessibility | **WCAG 2.2 AA**, as a dedicated workstream (Ant Design Vue is not headless/ARIA-first) |
| Backend | **API v2** (with v1 sunset policy), caching + DB optimization, security hardening |
| Extra scope | Frontend observability (web-vitals/RUM + errors) · Playwright e2e parity net · CSP + auth rate-limiting |
| Out of scope | OpenAPI-generated TypeScript client (considered, dropped) |

## Phase 0 — De-risking spike

A throwaway Nuxt POC that de-risks the riskiest unknowns before broad implementation. The rewrite decisions are already **Accepted**; the spike validates the hard mechanics and settles any remaining detail (notably ADR 024's CSP strictness).

| Unknown | What must be proven |
| ------- | ------------------- |
| **SSR + OIDC auth** | The confidential-client + resource-server flow ([ADR 004](/registry/technical/adr/004-oidc-resource-server-auth)) survives server rendering: httpOnly-cookie / server-session handling, token refresh, backend contract unchanged. *This is the sharpest consequence of choosing full SSR.* |
| **Ant Design Vue under SSR** | CSS-in-JS style extraction with no FOUC, theme tokens, bundle weight. |
| **Runtime config under Nuxt** | Keep "one immutable image, config injected at deploy" ([ADR 008](/registry/technical/adr/008-frontend-runtime-config)) via Nuxt `runtimeConfig`. |

**Outcome:** the spike confirms the hard mechanics (SSR auth, Ant Design Vue nonced styles / CSP, Nuxt runtime config) and may upgrade [ADR 024](/registry/technical/adr/024-frontend-security-headers)'s `style-src` to fully strict; findings feed back into the affected ADRs.

> **✅ Executed 2026-07-25** (`Registry-Spike/`, findings in its `SPIKE-FINDINGS.md`). All three unknowns validated end-to-end against local Keycloak + Spring: full-BFF SSR auth works with Spring's contract untouched (JIT provisioning confirmed through the proxy); AntD SSR style extraction gives a styled first paint with no FOUC; runtime config loads and fail-fast-validates at boot. Two decisions fed back: **[ADR 022](/registry/technical/adr/022-ssr-auth-bff)** — the single sealed cookie exceeded the 4 KB ceiling (5073 B), resolved by a two-cookie split (session 3483 B + id_token companion); **[ADR 024](/registry/technical/adr/024-frontend-security-headers)** — the strict `style-src` upgrade is **rejected** (ant-design-vue 4.x cannot nonce client-injected styles); the committed baseline (strict nonced `script-src`, pragmatic `style-src`) is final.

## Workstreams & spec artifacts

### Track A — Backend (independent; can start immediately)

> **A3 status (2026-07-26): backend items implemented, pending pattern validation.** Per [ADR 019](/registry/technical/adr/019-backend-security-hardening): §1 `RateLimitHandler` — per-user Bucket4j/Caffeine buckets on the sensitive-mutation and search categories, deploy-tunable, `429` + `Retry-After` in the localized `ErrorDto` shape; §3 `ApiHeadersHandler` (`nosniff` + `no-store` safety net — Spring Security already stamps authenticated responses); §5 `CorrelationIdHandler` (accept/generate `X-Correlation-Id`, echoed + Reactor context) and `AuditService` — append-only JSON entries on a dedicated logger (actor, action, target, outcome, correlation id), wired into the five privileged user actions as the reference instance; §6 `security-scan.yml` (gitleaks + trivy) complementing the existing CodeQL/dependency-review. Fixed on the way: `AuthorizationErrorHandler` had the same wrong-bundle key leak as the advice. Out of backend scope, tracked elsewhere: §2 network posture (infra), §4 token lifetimes (IdP/Nuxt — the BFF already enforces expiry + refresh + absolute session age), image scanning attachment to the release build, SIEM/durable sink for the audit logger, and replicating audit wrapping to the remaining privileged domains after validation.

> **A2 status (2026-07-26): implemented, pending pattern validation.** Reference instances per [ADR 018](/registry/technical/adr/018-backend-caching-db): `ReactiveCacheService` (Caffeine `AsyncCache` behind a `Mono` API) applied to the users hot-list **count** (TTL + eviction on writes); the **RBAC map** converted from load-once-at-startup to volatile snapshots with a scheduled reactive refresh (role changes no longer need a restart — a per-read cache doesn't fit its synchronous `PermissionEvaluator` consumers, a documented deviation); **ETag/Cache-Control/Vary** on metadata GETs with `304` revalidation (security-ordered); Flyway `V1_13_0` adding tenant-first composite indexes for every v2 sort column; R2DBC **pool sizing + prepared-statement cache** made deploy-tunable. Count strategy for project-scoped hot lists deferred to B2 when real usage exists.

> **A1 status (2026-07-25): IMPLEMENTED across all domains.** The v1 sunset machinery (`Deprecation`/`Link`/optional `Sunset` on `/api/v1/**`) plus the complete `/api/v2` surface per the [API Reference](/registry/technical/api-reference): users (validated reference), authentication, preferences, my-profiles, projects, project-profiles, participants, groups, movements, vehicles, activities, communications, alerts, metadata, purge — uniform `page`/`size`/`sort`/`q`/typed-filter grammar (whitelisted-enum sort pushed into SQL), explicit `POST` transitions (incl. alerts `resolve`/`cancel`/`reopen`, profiles `accept`/`reject`), eligibility renames (`assignable-`/`linkable-`/`eligible-`/`attachable-`), `PATCH /{id}` body edits, authorities copied verbatim from v1. v1 frozen and untouched; full build (tests, ArchUnit, coverage) green; sampled endpoints verified live. ~85 new v2 tests. Fixed on the way: error responses leaked raw i18n keys (advice read the wrong bundle). Known limits: pickers stay bounded `Flux` (no page envelope, faithful to v1 services); sort applies to root collections (sub-lists keep fixed ordering); purge crons stay solely on v1 until sunset.

> **B1 status (2026-07-25): implemented, pending pattern validation.** The foundation lives in `Registry-Frontend-Nuxt/` — Nuxt skeleton, BFF auth (hardened per the spike findings: two-cookie session, size assertion, anonymous-cookie suppression), runtime config with the [ADR 013](/registry/technical/adr/013-ant-design-vue) theme/assets shape, Pinia stores consumed directly ([ADR 014](/registry/technical/adr/014-pinia-state-management) as amended 2026-07-25) with the reset-cascade seam, AntD SSR theming (SYSTEM/LIGHT/DARK, SSR-resolved), final [ADR 024](/registry/technical/adr/024-frontend-security-headers) CSP, the [ADR 020](/registry/technical/adr/020-frontend-observability) telemetry seam, shell a11y patterns, and the vitest+axe reference tests. Per the working agreement, each pattern is a **reference instance** (map in that repo's `AGENTS.md`) awaiting validation before replication in B2.

**Two hard cross-track gates:**

1. **API v2** must be spec-stable before the frontend (B2) builds against it.
2. Any **role / auth** change (A3) must be frozen before the frontend guards are written — the frontend mirrors backend authorities.

## Cutover

A full rewrite means a **big-bang cutover per environment** (dev → staging → prod), each gated by the Playwright parity suite (ADR 021). Both services ship immutable images via semantic-release ([ADR 010](/registry/technical/adr/010-container-delivery-semantic-release)), so cut over **blue/green at the ingress / nginx layer** and keep **v1 alive under the sunset policy** (ADR 017) until the Nuxt frontend fully replaces the Angular one.
